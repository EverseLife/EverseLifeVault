# Технические заметки

> **Статус:** черновик v0.1 — не архитектура, а ограничения, вытекающие из дизайна

Этот документ не проектирует систему. Он фиксирует, **что дизайн требует от техники**, чтобы при выборе стека не выяснилось, что ключевая механика невозможна.

## Требования, вытекающие из дизайна

| Требование | Откуда | Последствие |
|---|---|---|
| Мир живёт без игроков | Асинхронность, [20-systems/01](../20-systems/01-time-model.md) | Нужен серверный тик и планировщик отложенных событий, а не только обработка запросов |
| Полное событийное логирование | Суд, метрики, расследования | Event log как первичное хранилище; состояние — производное |
| Транзакционность экономики | Деньги и предметы | Строгая согласованность на сделках. Никаких «примерно» |
| Книга заявок | [30-economy/02](../30-economy/02-markets.md) | Матчинг-движок, пусть простой |
| Права доступа на всё | Контракты, доли, должности | Гибкая модель прав, а не хардкод ролей |
| Изменяемые правила городов | [40-society/02](../40-society/02-law-engine.md) | Код-законы как данные, интерпретируемые движком, а не как ветвления в коде |
| Реальное время в чате и сценах | Живое общение, забой, торги | WebSocket / SSE |
| **Интерактивный клиент** | D-042: клики вместо команд | Полноценное SPA; сцены и карта — canvas или SVG, а не DOM-таблицы |
| **Масштабируемая карта-граф** | D-045 | Рендер графа с зумом и слоями; путь строится на сервере, рисуется на клиенте |
| **Хранение изображений локаций** | D-046, D-073 | Объектное хранилище, CDN, два размерных класса (баннер и фон). Загрузок в игре нет вовсе: приём и курирование живут на отдельном сайте, игра только читает готовый набор |
| **Группы внутри локации с утечками** | D-043 | Маршрутизация сообщений с вероятностью доставки в соседнюю группу |
| **Удалённое управление ордерами** | D-047 | Ордер живёт на сервере независимо от местонахождения игрока |
| Пуш-уведомления | [50-interface/04](../50-interface/04-notifications.md) | PWA или мобильное приложение |
| Античит-телеметрия | [60-meta/01](../60-meta/01-anti-cheat.md) | Хранение поведенческих метрик с первого дня |
| Read-only API, никакого API действий | Античит | Все действия — только через сессию клиента |
| **Балансные константы в рантайме** | D-065 | Ни одна цифра не зашита в код: конфиг с горячей перезагрузкой, админ-панель, **лог всех изменений** |
| **Процедурная генерация рецептов** | D-061, Аврора | Генератор, масштабирующий сложность по глубине комплекса |
| **Проверка различия сортов** | D-067 | Сравнение нового сорта с существующими по совокупности признаков при попытке прорастания |

**Самый нетривиальный пункт — код-законы как данные.** Если законы городов реализовать ветвлениями в коде, каждый новый тип закона потребует релиза, и вся идея «игроки пишут правила» умрёт. Нужен небольшой декларативный слой: закон = запись с типом, параметрами и областью действия, а движок при каждом действии проверяет применимые записи.

## Масштаб

Даже с интерактивным интерфейсом (D-042) серверная нагрузка остаётся скромной: нет физики, нет непрерывных позиций, нет синхронизации движения. Вся графика живёт на клиенте, сервер оперирует состояниями и транзакциями. Основная нагрузка — **транзакции, чат и рассылка событий**.

Ориентир: несколько тысяч одновременных игроков — задача, решаемая одним сервером с нормальной БД. Это принципиально проще, чем графическая MMO, и позволяет сосредоточиться на дизайне.

Узкие места, когда они появятся:
- Матчинг заявок на популярных рынках
- Рассылка сообщений в каналы
- Тик мира при большом числе длительных действий

## Выбор стека (не решено, ориентиры)

Что важно при выборе:
- Хорошая работа с долгоживущими соединениями
- Надёжные транзакции (реляционная БД — почти наверняка)
- Удобство описания игровых правил как данных
- Скорость итерации на этапе прототипа важнее производительности

Прототип (Э0–Э1) можно и нужно делать на том, на чём быстрее пишется. Проект в PyCharm намекает на Python — для прототипа и симуляции экономики это отличный выбор.

## Симуляция экономики

Отдельный инструмент, не часть игры: агентная модель, прогоняющая 30 игровых дней с популяцией ботов-агентов, чтобы ловить экономические катастрофы до плейтеста ([30-economy/05](../30-economy/05-balance-model.md)).

Это стоит написать **до** основного кода. Дёшево и спасает месяцы.

## Данные, которые надо хранить с первого дня

Даже если пока не используются:
- Все транзакции
- Все действия игроков с временными метками
- История цен и сделок
- История законов, приговоров, голосований

Потом восстановить это невозможно, а понадобится всё.

## Открытые вопросы

- Выбор стека и БД
- Веб-клиент: SPA или server-rendered с живыми обновлениями
- Хостинг и стоимость (влияет на монетизацию)
- Резервное копирование и откаты: как откатывать экономику после эксплойта, не разрушая доверие
