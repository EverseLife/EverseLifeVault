# Карта реализации

> **Статус:** живой (D-137) · **Для кого:** тот, кто ставит задачи агенту-разработчику
>
> Что дать на вход под каждую задачу. Вольт целиком не даётся никогда — шестьдесят документов в контексте не улучшают ответ, а размывают его.

---

## Правило среза

На одну задачу — **2–4 документа, нужные `D-XXX` и данные**. Больше не нужно, меньше опасно.

Обязательный минимум в любом срезе:

1. **[CLAUDE.md](../CLAUDE.md)** — правила вольта: числа только из `data/`, статус как контракт
2. **[05-domain-model](05-domain-model.md)** — что существует в мире и что чем владеет
3. **[06-actions](06-actions.md)** — раздел про ту систему, которую делаем
4. **`build/*.json`** — то, что читает движок. **Единственная спецификация чисел**

Дальше — срез по таблице ниже.

## Приёмка

Критерий готовности задачи — **не «работает», а «инвариант держится»**.

1. **Инварианты И1–И13** из [балансной модели](../30-economy/05-balance-model.md). Каждый обязан иметь автоматическую проверку на телеметрии
2. **Симуляция** `python tools/simulate.py` — гонять при любом изменении констант. Арифметической части отчёта верить можно, рыночной — только как сигналу
3. **Сборка** `python tools/build.py --check` — обязана быть зелёной до коммита

## Что обязан делать агент

Четыре правила, нарушение любого — откат:

| Правило | Почему |
|---|---|
| **Ни одного балансного числа в коде.** Всё из `build/constants.json`, с горячей перезагрузкой | D-065: константа меняется без выката версии |
| **Взял задачу — перевёл документ в «в реализации».** Сдал — в «реализовано» | Статус это контракт синхронизации, а не украшение |
| **Расхождение с документом — вопрос, а не молчаливая правка** | Документ либо прав, либо устарел; решает человек, а не агент |
| **Правки чисел и рецептов — только в `data/`, потом `python tools/build.py`** | Правка сгенерированного markdown будет затёрта |

## Что живёт не здесь, а в репозитории игры

Вольт этого не содержит намеренно, и агент обязан написать это сам — **в своём репозитории**, не в вольте:

- Выбор стека, БД и хостинга ([01-tech-notes](01-tech-notes.md) фиксирует только требования)
- Схема хранения, миграции, событийный лог
- API и протокол клиент-сервер
- Тесты, CI, откаты
- Вёрстка и компоненты интерфейса

Правило разделения простое: **вольт отвечает на «что должно быть верно и почему», репозиторий игры — на «как именно это сделано»**.
